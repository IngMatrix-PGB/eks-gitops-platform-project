# Runbook: The reference application's data store

**Phase 6.3b. Local kind labs only. `ACTUAL COST: USD 0`.**

The reference application ([ADR-0023](../adr/0023-reference-application.md))
is three components in one environment namespace:

- `smoke` (Go), the edge; `GET`/`POST /api/notes` forward to notes;
- `notes` (Python), which owns the data;
- `postgres`, from `charts/postgres-lab`.

Argo CD delivers them from 6.3c. This runbook covers what lives outside
Git: the database credentials.

## Credentials

One Secret per environment, `eso-source-<env>/db-<env>`, with two keys:

- `superuser-password`: the `postgres` superuser, used only by the
  database container;
- `app-password`: the `notes` login role, used by the notes workload.

Create it, and its reader RBAC, once per environment:

```bash
make eso-provision-db-secret ENV=dev
```

- Both values are random, generated by the script, and never printed.
- If the Secret exists it is left exactly as it is: never read, never
  rotated. A re-run only re-applies the Role and RoleBinding
  `db-<env>-reader`, which let `<env>-postgres-reader` and
  `<env>-notes-reader` read that one Secret.
- `make eso-install` must have created `eso-source-<env>` first.
- Velero backs this Secret up with the rest of the source namespace
  (ADR-0022); a restore brings the same values back.

## How the passwords reach the pods

- `charts/postgres-lab` has its own SecretStore and ExternalSecret; both
  passwords are mounted read-only at `/run/secrets/postgres` and read
  through `POSTGRES_PASSWORD_FILE` and the init script.
- The notes workload's ExternalSecret maps `app-password` to the file
  `/var/run/secrets/notes-db/password`. Notes reads the file on every
  new connection.
- No password is ever an environment variable or a chart value:
  `standard-workload`'s schema rejects `extraEnv` names that look like
  credentials.

## The database is initialised once

The `notes` role and its grants are created by the init script only when
the data directory is empty (the first start on a new PVC). Changing
`app-password` in the source Secret afterwards does not change the role's
password in PostgreSQL. Until a rotation procedure exists, a new password
needs a new, empty volume.

## The volume

- The PVC `data-<release>-0` is retained when the StatefulSet is deleted
  or scaled down. Deleting it deletes the data.
- There is no logical dump yet (TAD R-19); 6.3d adds one to the backup
  store.

## Checks

- `make check-postgres-lab-chart`: the chart's objects, pinned digest,
  restricted pod, password files only, retained PVC, NetworkPolicy.
- `kubectl -n <env> get externalsecret` on the spoke: both
  `SecretSynced`.
- `notes` `/readyz` answers 503 until its table exists and while the
  database is unreachable; smoke answers 502 when notes fails.
